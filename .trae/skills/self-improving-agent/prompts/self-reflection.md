# Self-Reflection Prompt

Use this prompt after completing a task to analyze what went well and identify improvements.

## When to Use

- After completing complex tasks
- When encountering errors or unexpected outcomes
- During code review and optimization phases
- After receiving user feedback

## Reflection Structure

### 1. Task Outcome Analysis

Evaluate the final result:
- Did we achieve the goal?
- What specific aspects worked well?
- What could have been done differently?

### 2. Error Pattern Recognition

Identify any issues:
- Were there any bugs or errors? What caused them?
- Did we miss any edge cases?
- Were there any misunderstandings about requirements?

### 3. Improvement Opportunities

Document potential improvements:
- What approaches should we avoid in the future?
- What patterns worked well that we should reuse?
- What new techniques did we discover?

### 4. Knowledge Transfer

Extract reusable insights:
- What lessons can be applied to similar tasks?
- What documentation should be updated?
- What best practices should we follow going forward?

## Questions to Ask

1. What was the most challenging part of this task?
2. How did we handle unexpected complications?
3. Was our initial approach correct, or did we need to pivot?
4. What would we do differently if we started over?
5. Did we learn anything new that applies to future tasks?

## Output Format

```markdown
## Self-Reflection Report

### Outcome: [Success/Partial/Failed]

### What Went Well
- [Point 1]
- [Point 2]

### What Could Be Improved
- [Point 1]
- [Point 2]

### Key Learnings
- [Learning 1]
- [Learning 2]

### Action Items
- [ ] Improvement to implement
- [ ] Pattern to remember
```

## Best Practices

1. Be honest and objective in your analysis
2. Focus on actionable improvements
3. Document both successes and failures
4. Look for patterns across multiple tasks
5. Update relevant documentation with new insights
